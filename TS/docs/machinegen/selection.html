Selection and Navigation

Selection shapes, movement, expansion, parent/child traversal, and matching-cell jumps.

Updated last on 2026-05-09 · Source commit 84ef9b924c79
Machine-assisted reference docs. Reliability indicators and footnote citations are included with every section.

TreeSheets uses one selection model for cells, grid lines, and text cursors. Many commands first expand thin grid-line selections or single-cell selections before acting.

Move, extend, and move cells

Code verified

Arrow keys move the current selection, or the text cursor when you are editing a cell. `Ctrl+Arrow` moves selected cells around inside the grid. `Shift+Arrow` extends the current cell or text selection.

  • Movement acts on the active grid selection. In text edit mode, the same arrow shortcuts move or extend the text cursor selection.
  • Moving cells is undoable and TreeSheets scrolls or zooms enough to keep the selection visible. Shift expansion changes the selection rectangle while staying inside the grid.
  • On GTK, several arrow, tab, and page-key shortcuts are handled directly because the toolkit does not expose them as normal menu accelerators.

Ctrl+I can arrive as Ctrl+Tab on Linux, so Ctrl+Tab tab switching is intentionally ignored there and Ctrl+Shift+Tab remains the reliable previous-tab shortcut.

Select all, parent, and first child

Code verified

Select all selects every cell in the current grid, or all text in the current cell when already in text edit mode. Esc exits text edit mode; outside text edit mode it selects the parent cell, or the entire root grid if there is no parent. Entering a child grid selects the first cell of an existing subgrid, or creates a new 1x1 subgrid when none exists.

  • Select all requires a current grid. Parent traversal needs a grid selection; child traversal requires a single expandable cell.
  • Selection coordinates are rewritten to the target grid or parent cell. Creating a subgrid records undo, creates the grid, selects its first cell, and refreshes the canvas.
  • Esc in text edit mode may undo coalesced text entry before leaving edit mode. Creating an NxN grid prompts for size and can be cancelled.

The same user action can either enter an existing child grid or create a new child grid, depending on whether the selected cell already contains one.

Sort rows and jump to matching cells

Code verified

Sorting rearranges rows based on a one-column selection. Matching-cell commands jump to another cell with the same text, or to another cell using the same image, in forward or reverse search order.

  • Sorting needs a 1xN selection that identifies both the sort key column and the rows affected. Matching by text needs a selected cell with text; matching by image needs a selected cell with an image.
  • Sorting is undoable and redraws the grid. Matching changes the selection to the next matching cell and scrolls or zooms as needed to make it visible.
  • If there is no matching cell, TreeSheets reports that no match was found. Matching compares cell text or image identity, not the visible formatting around it.

The sort menu text gives the main selection rule, but sorting complex nested data still deserves manual checking before relying on it for important data cleanup.
